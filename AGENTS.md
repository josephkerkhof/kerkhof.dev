# Project Instructions

## Changelog

Document every notable user-facing or architectural change in `CHANGELOG.md` under `[Unreleased]`.

Use the appropriate Keep a Changelog heading: `Added`, `Changed`, `Deprecated`, `Removed`, `Fixed`, or `Security`.

Update the changelog before committing. Documentation-only changes and insignificant internal changes do not require an entry.

## Verification

Run `make build` after changing site content, layouts, configuration, or styles.
